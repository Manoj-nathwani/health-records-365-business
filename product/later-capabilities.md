# Later capabilities

Source: [Competitive Research](../Inbox/health-records-365-competitive-research.md) §19.

Validated by the market, but **not core positioning**. Build when a real customer need forces it, not to match a competitor's feature list — all of these are [table stakes](../market/table-stakes.md) elsewhere.

**Translation** — useful for cross-language healthcare. Offered by [RinVita](../market/competitors/rinvita.md) and [SIP](../market/competitors/sip-medical-family-office.md).

**Emergency medical summary** — medications, allergies, diagnoses, procedures and emergency contacts.

**Medical imaging archive** — original imaging files (DICOM) where appropriate.

**Insurance-document support** — help with insurer requests, pre-authorisation and claims.

**Family management** is no longer on this list — it is the content of [the premium tier](../commercial/layers.md). What remains deferred is the *delivery machinery* for it: permission models, proxy mandates and multi-member record separation, built when the first family customer forces them.

**International Patient Summary** — potentially generate an IPS-compatible portable summary. See [interoperability](../strategy/interoperability.md).

## Why deferred

Each of these adds delivery cost before the [labour economics](../go-to-market/labour-economics.md) of the core service are understood. The [validation plan](../go-to-market/validation-plan.md) should observe which ongoing jobs customers actually ask for — that demand, not this list, sets the order.
